## 2. 我们要做什么

> 一个给客服质检分析员用的系统：**上传一通客服录音和该客户的历史联系记录，
> 它重建这一单投诉升级的因果链，指出最早本可以阻断的那一刻，并把每条结论回溯到对话原文。**

它**不是**：不是客服机器人，不跟客户对话，不自动执行退款或工单。
它是**分析员的副驾**，输出是给人看、给人决策的。

### 与现有产品的区别（这句话必须能原样说出来）

> Observe.AI 给的是一个**升级风险分数**。CallMiner 给的是**聚合的根因趋势**。
> 两者都不告诉运营者**这一单**为什么会走到升级，也不指出**最早能阻断的那一刻**。
> 我们输出的是一条可回溯到对话证据的**因果时间线**，终点是一个可执行的动作。

详见 [竞品补充说明](proposals/complaintguard-competitive-note.md)。

## 4. 架构

```
①  音频摄取        上传 → 分块（2–3 秒），不做真流式
②  转录 + 说话人分离  ElevenLabs Scribe
③  结构化抽取       诉求 / 约束 / 承诺 / 截止时间 / 已执行动作      ← LLM
④  跨通话状态跟踪    把本通与历史记录合并成一条案例时间线
⑤  解决度匹配       每条诉求 → 客服是否真的处理了                  ← LLM
⑥  规则与计时       承诺 24h vs 实际 72h、重复联系次数、监管词      ← 确定性代码
⑦  风险融合         多信号加权，阈值固定                          ← 确定性代码
⑧  阻断点识别       在时间线上回溯最早的可干预节点                  ← 确定性代码
⑨  证据绑定         每条结论挂上转录中的原句 + 时间戳
```

**③⑤ 用 LLM，⑥⑦⑧ 用普通代码。** 理由要能在台上说出来：

> 理解自然语言用模型；**任何会影响人的判断（打分、定责、触发动作）用确定性规则，
> 因为它必须可审计、可复现、不会幻觉。**

这正是赞助商自己的原则，也是技术难度那 8 分的抓手。

## 5. 需要哪些材料

**我们没有真实数据，这是最大的工程约束。以下全部要自己造。**

> ⚠️ **绝对不使用中国移动实习期间接触过的任何真实录音、转录、工单或客户信息。**
> 行业知识可以用，数据一律自己生成。视频和 README 里必须写明"全部为合成数据"。

### 5.1 通话脚本（20–30 个场景）

每个场景是一段客户↔客服对话，**写脚本时就确定好正确答案**。
这是整个项目的地基——**因为我们写了脚本，所以我们精确知道承诺了什么、哪条没兑现。
这就是 ground truth，不用另外标注。**

每个场景需要覆盖：

- 客户诉求 1–3 条（至少一条不被解决）
- 客服承诺 0–2 条（至少一半不兑现）
- 明确的截止时间（"24 小时内回电"）
- 是否出现监管词 / 转网意向
- **标准答案**：哪条诉求未解决、哪条承诺未履行、该不该升级、根因分类、最早阻断点

**场景要有难的**：情绪平静但直接找监管的、情绪激动但其实已解决的、
承诺被部分兑现的——**这些是证明系统不是在做情绪分析的关键样本。**

### 5.2 通话音频

**用 ElevenLabs TTS 把脚本变成音频，客户和客服用两个不同音色。**

这一步同时解决三件事：

1. 拿到可上传、可演示的真实音频文件，零隐私风险
2. **让 ElevenLabs 成为流程的核心环节**（TTS 造语料 + STT 转录），特别赛道站得住
3. 音色一致、可重复生成，评测可复现

⚠️ Creator 额度有限，**脚本定稿后再批量生成，别在调试时反复烧**。

### 5.3 历史联系记录（合成 CRM）

JSON 格式，每个案例配 1–3 条前序记录：

```json
{"case_id":"C017","contacts":[
  {"seq":1,"date":"2026-09-03T10:12","channel":"call",
   "summary":"客户要求取消附加包并退费","promises":[
     {"text":"24 小时内回电确认","due":"2026-09-04T10:12","fulfilled":false}],
   "resolved":["取消附加包"],"unresolved":["退费两个月"]},
  {"seq":2,"date":"2026-09-05T09:40","channel":"call","summary":"客户追问退费进度"}
]}
```

### 5.4 电信投诉分类法（小而具体）

来自 Genicayyy 的行业知识，不是数据：

- 投诉类型：计费争议、附加包未授权、网络质量、套餐变更、退费、服务态度
- 承诺类型：回电、工单、退费、升级主管、技术上门
- 根因分类：回电未兑现、权限不足、需求被误解、反复转接、政策空白
