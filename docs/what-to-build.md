# 到底要做什么、交什么

从「最后交什么」倒推回「现在选什么题」。

---

## 一、交什么：四样东西，就这些

周一 12:00 在 Devpost 上交：

| # | 交付物 | 具体长什么样 |
| --- | --- | --- |
| 1 | **Devpost 项目页** | 标题、描述（**必须写明投哪个赛道**）、下面三样的链接 |
| 2 | **公开 GitHub 仓库** | 评委会点进来看代码结构和 README。**代码质量 6 分靠这个** |
| 3 | **线上可访问的 URL** | 评委在自己浏览器里打开就能用。localhost 明确扣分 |
| 4 | **3–5 分钟视频** | 录屏，展示应用**真实跑通**。不能是 PPT 配旁白 |

**初赛 80 分全部从第 2、3、4 项评出来。** 评委不会跟你面对面，他们看视频、点开你的网站、翻你的仓库。

进前 8 才有决赛：现场 3–5 分钟 **live** demo + 答辩，不接受录播。

## 二、你交的不是「一个 Agent」，是一个网页

这一点很多人搞混。评委打开你的 URL，看到的应该是：

```
┌─────────────────────────────────────────┐
│  输入区                                  │
│  ← 上传文件 / 粘贴文本 / 说话 / 选场景    │
├─────────────────────────────────────────┤
│  结果区                                  │
│  ← 一个明确的产出：判断、文档、清单、告警  │
├─────────────────────────────────────────┤
│  「为什么」面板                           │
│  ← 每条结论来自哪个原文、哪条规则          │
└─────────────────────────────────────────┘
```

第三块是业余和专业的分界线。**能指出证据来源的系统，评委才敢信。** 这也是可行性 8 分和
负责任 AI 那条线的抓手。

Agent 是引擎，网页是车。**交的是车。**

## 三、切入点的通用形状

看赞助商那四个案例，它们是**同一个形状**：

| 案例 | 杂乱输入 | 结构化产出 | 效果 |
| --- | --- | --- | --- |
| 私募信贷 | 150 页估值报告 + 407 变量 Excel + 借款人 PDF | 投资意向书、贷款备忘录 | 52 分钟 → 30 秒 |
| 拍卖行 | 8–9 万条客户历史、竞拍记录 | 「该联系谁、推荐哪件拍品」的名单 | 25 小时 → 2–3 小时 |
| 发票对账 | 一堆格式不一的发票 | 结构化数值 + 异常清单 | 人工复核 100% → 8% |
| 土地估值 | 周边成交、地段资料 | 5 页投资级分析报告 | 几天 → 几小时 |

**通用形状：**

> **某个岗位的人，每 [频次] 要把 [一堆杂乱输入] 变成 [一个结构化产出]，
> 花 [时长]，做错了会 [后果]。**

这四个空填得出来，就是好题；填不出来，就还不是题。

注意：**产出必须是「人现在手工在做的东西」**。不是「一个聊天机器人」，
是一份报告、一个判断、一张清单、一个告警。因为只有这样才有工时基线，才算得出钱。

### 自检三问

1. 这个产出，现在是谁在手工做？**说不出具体岗位就换题。**
2. 他做一次要多久？**说不出时长就填不了「今天花 $X」。**
3. 做错了会怎样？**说不出后果，就证明这件事不重要。**

## 四、Agent 内部怎么分层

技术难度 8 分明确扣罚「套壳现有 API」。要拿分，架构必须能讲出为什么。

```
① 摄取      解析杂乱输入（PDF / Excel / 音频 / 网页 / 聊天记录）
② 抽取      把事实抠出来，并记录每条事实来自原文哪一句
③ 检索      拉取参照资料（规则、要求、历史、价目）
④ 判断      ← LLM 在这里。需要理解、归纳、写解释的部分
⑤ 计算      ← 普通代码在这里。算术、阈值、规则判定，绝不交给 LLM
⑥ 生成      产出结构化文档 / 决策 / 清单
⑦ 证据      每条结论可回溯到 ② 或 ③ 的来源
```

**④ 和 ⑤ 的切分是这次比赛的送分题。** 赞助商原话：涉及金额的地方
用确定性管线，而不是可能出错的 Agent。台上说得出这个切分和理由，
技术难度那 8 分就稳了。

反过来：整个流程一个大 prompt 打天下，就是评分表说的 wrapper，封顶 3–4 分。

## 五、资料从哪来（48 小时内最现实的问题）

你**没有**真实企业数据。五种来源，按加分从低到高：

| 来源 | 说明 | 风险 |
| --- | --- | --- |
| ① 公开数据集 | Kaggle、政府开放数据、ABS | 常常跟你的业务场景对不上 |
| ② **合成数据** | 用 LLM 生成逼真的文档/记录/对话 | **完全可以，但必须在视频和 README 里说明是合成的** |
| ③ 公开可抓取 | 大学录取要求、公开挂牌、企业公告 | 注意 robots.txt 和频率 |
| ④ **你自己手上的** | 你打工时的表格、社团记录、家里生意的单据（脱敏 + 获得同意） | **最有说服力**，评委会觉得你真懂 |
| ⑤ **评委当场给的输入** | 让评委上传/粘贴/说他自己的东西 | **最强的一招** |

⑤ 为什么最强：功能完整度 9–10 分要求「完整可用、优雅处理边界情况」，
5–6 分是「需要特定的演示路径才能跑通」。**如果系统只在你准备好的五个文件上能跑，
就是 5–6 分。** 而决赛是现场 demo，评委很可能会当场试。

**所以从第一行代码起就按「任意输入都能进」来设计。**

### 你需要准备的数据清单

- **10–30 份输入样本**（真实或合成），**必须包含几份「难看的」**——格式错乱、缺字段、
  单位不一致。演示时敢放一份脏数据进去，说服力翻倍
- **20–30 份标注好的样本**用于评测：输入 + 正确答案。这是数据与模型那 6 分的依据
- **参照资料**：系统要查的规则、要求、价目表
- **一条「评委自己试」的入口**

## 六、三个填满的例子（是示范，不是选项）

展示一份完整的答案长什么样。**照着这个粒度去填你自己的题。**

### 例 A：留学中介的申请预审

- **谁在痛**：3–10 人的留学中介顾问，手上同时带 40 个学生
- **杂乱输入**：成绩单（各国格式、各种评分制）、语言成绩、CV、个人陈述、护照页
- **结构化产出**：每个学生 × 每个目标专业的**资格比对报告** —— 满足什么、缺什么、
  差多少、还能补什么
- **现在怎么做**：顾问手工翻大学官网逐条对照，一个学生 1–2 小时
- **做错了**：学生投了根本申不上的项目，申请费打水漂、错过轮次、中介口碑受损
- **参照资料哪来**：**大学录取要求是公开的**，可抓取
- **④/⑤ 切分**：GPA 换算、学分比对、要求判定 → **全部确定性代码**；
  读懂杂乱文档、写解释和建议 → LLM
- **评测**：合成 30 份学生档案（正确答案已知）→ 资格判定的准确率/召回率
- **评委能自己试**：粘贴任意一份成绩单

### 例 B：补习机构的课时对账

- **谁在痛**：单校区补习机构的行政老师
- **杂乱输入**：签到表、微信里的请假消息、补课记录、缴费流水
- **结构化产出**：每个学生的课时余额 + **异常清单**（对不上的、该催费的、快用完的）
- **现在怎么做**：每周手工核对 Excel，200 个学生要小半天
- **做错了**：家长投诉、该催的费没催、退费纠纷
- **④/⑤ 切分**：课时加减 → **纯代码**；从微信消息里读出「这是请假还是调课」→ LLM
- **评测**：合成一个月的记录，正确余额已知 → 对账准确率
- **评委能自己试**：上传一份乱七八糟的签到表

## 七、一句话自检

能把下面这段话补完整，题就成立了：

> **「[某岗位] 每 [频次] 花 [时长] 把 [杂乱输入] 变成 [结构化产出]，
> 做错了会 [后果]。我们的系统把这件事变成 [新时长]。
> 评委可以自己上传 [某种输入] 当场验证。」**

补不完整，就还没到能开工的程度。
